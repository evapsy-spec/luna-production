# Luna Production — EVA MOON

Приложение для управления производством: ткани → фабрики → коллекции → заказы
на пошив → аналитика. Открывается с телефона, планшета и компьютера, данные по
остаткам и продажам подтягиваются из AinurPOS.

---

## Быстрый старт

```bash
npm install
cp .env.example .env        # заполнить SESSION_SECRET и (позже) AINUR_API_TOKEN
npm run db:migrate          # создать таблицы
npm run db:seed             # демо-данные EVA MOON, чтобы было что смотреть
npm run dev                 # http://localhost:3000
```

Демо-пользователи (пароль у всех `luna2026`):

| Email                    | Роль     | Что видит                                    |
| ------------------------ | -------- | -------------------------------------------- |
| `eva@evamoon.co`         | владелец | всё, включая себестоимость и оплаты фабрикам |
| `konstantin@evamoon.co`  | владелец | всё                                          |
| `manager@evamoon.co`     | менеджер | производство без денежных сумм               |

`npm run db:reset` — полный сброс базы и повторное наполнение демо-данными.

`npm run db:fresh` — **чистый старт перед первой синхронизацией с живым
Ainur**: удаляет все данные, кроме пользователей и токена, и создаёт склады
тканей. Нужен потому, что демо-коллекции называются как настоящие, но
привязаны к вымышленным id категорий — после синхронизации получились бы дубли.

## Что уже работает

**Главная** — заказы в производстве, товар на складах, бюджет в производстве,
просрочки, топ коллекций, что заканчивается, что лежит в избытке (кандидаты на
скидку), рекомендации по перемещению между складами, производство по месяцам,
скоркард фабрик, рекомендация Luna «что отшить на 3 месяца вперёд».

**Ткани** — каталог с остатками по нескольким складам, резерв под заказы,
цена в валюте закупки с фиксацией курса на дату закупки, поставщики с WhatsApp
и маршрутом в Google Maps, рулоны с QR-метками для учёта телефоном на складе,
печать меток.

**Фабрики** — контакты, WhatsApp, маршрут, специализация, какие коллекции шьёт
(одна коллекция может шиться на нескольких фабриках), фиксированные цены пошива
за изделие с историей, индикатор загрузки, автоматический скоркард: % заказов
вовремя, % брака, суммы заказов и оплат. Есть страница сравнения фабрик.

**Коллекции** — иерархия коллекция → изделие → вариант (SKU как в Ainur),
остатки по складам, BOM (состав изделия: расход каждой ткани на 1 шт + припуск
на раскрой + фурнитура), технические лекала файлами, себестоимость 1 изделия.

**Заказы на пошив** — выбор фабрики и горизонта планирования (N месяцев,
настраивается под каждый заказ), рекомендация Luna, автоматический расчёт
расхода тканей по BOM, сверка с остатками, резерв метража при создании,
автосоздание черновика заявки на дозакупку при нехватке, снэпшот себестоимости,
обязательный этап образца перед массовым пошивом, плановые даты, учёт оплат,
брак со списанием в следующий заказ этой фабрики, спецификация для фабрики
на печать и в WhatsApp.

**Аналитика** — продажи по коллекциям с графиками, лучшие и худшие модели,
запас в месяцах, рекомендации по перемещению.

**Прочее** — календарь запуска коллекций, заявки на дозакупку ткани, фурнитура,
экспорт всей базы в Excel, аудит-лог всех изменений, синхронизация с Ainur.

## Синхронизация с AinurPOS

Ainur — источник правды по товарам, остаткам, продажам и перемещениям.
Luna ничего не записывает обратно в Ainur, только читает.

**Как получить токен:** AinurPOS → Integration → Connect API → «Generate a
token» → уровень доступа **Readonly** (Luna только читает, больших прав ей не
нужно). Ainur показывает токен целиком один раз — скопируйте его сразу.

**Куда вставить.** Проще всего — в самом приложении: страница
«Синхронизация» → поле «Вставьте токен Ainur» → «Сохранить и проверить».
Токен сохраняется в базу, приложение сразу проверяет подключение и показывает
результат. В интерфейсе он потом виден только последними символами.

Второй способ — переменная окружения `AINUR_API_TOKEN` (удобно на продакшене,
где секреты задаются в панели хостинга). Если токен задан и там, и в
интерфейсе, приоритет у введённого в интерфейсе.

Поле доступно только владельцам; менеджер производства токен не видит и не
меняет.

Дальше на странице «Синхронизация» кнопка «Обновить» подтягивает данные
(по решению Евы — вручную, не по расписанию).

Используемые эндпоинты (`https://connect.ainur.app/api/v4`, заголовок
`X-AINUR-API-Access-Token`):

| Эндпоинт             | Что берём                                                     |
| -------------------- | ------------------------------------------------------------- |
| `GET /stores`        | склады и точки — чтобы связать ID из `stock` с названием       |
| `GET /product`       | товары + **остаток по складам прямо в поле `stock`**           |
| `GET /product/ext-categories` | коллекции (группы Ainur)                             |
| `GET /product/updated` | инкрементальная синхронизация                               |
| `GET /documents/sales` | продажи за период — для скорости продаж                     |
| `GET /documents/changes` | **перемещения между складами** (`source` → `destination`) |

Ограничение Ainur: у `/documents/*` период не больше 31 дня. Клиент сам режет
длинные интервалы на месячные окна (`splitRange`), так что запрашивать можно
любой диапазон.

Ключ сопоставления товаров — поле `code` в Ainur = `sku` в Luna.

## Архитектура

```
src/
  app/                    страницы (Next.js App Router, Server Actions)
  components/ui.tsx       UI-кит: Card, Button, Field, StatusPill, Money, Table…
  components/charts.tsx   графики на чистом SVG, без внешних библиотек
  components/nav.tsx      навигация: нижняя панель на телефоне, меню на десктопе
  lib/db/schema.ts        схема данных (Drizzle ORM)
  lib/db/client.ts        подключение к базе
  lib/ainur/client.ts     клиент Connect API
  lib/ainur/sync.ts       синхронизация Ainur → Luna
  lib/production.ts       ядро: расход тканей, себестоимость, скорость продаж,
                          рекомендации, скоркард фабрик
  lib/auth.ts             вход, роли, аудит-лог
  lib/uploads.ts          фото и лекала
  proxy.ts                отсекает анонимные запросы
scripts/migrate.ts        применение миграций
scripts/seed.ts           демо-данные
drizzle/                  SQL-миграции (генерируются drizzle-kit)
```

### База данных

Разработка — **SQLite** через встроенный в Node 22+ модуль `node:sqlite`:
никаких нативных сборок и скачивания бинарников. Подключён к Drizzle через
драйвер `sqlite-proxy`.

Одна тонкость, о которой стоит знать при доработке: в адаптере включён
`stmt.setReturnArrays(true)`. Это обязательно — в JOIN-запросах несколько
таблиц дают одноимённые колонки (`products.id`, `collections.id`), и в
режиме объектов они затирают друг друга, часть значений теряется молча.

### Денежные правила

- Себестоимость заказа **фиксируется на момент создания** (`snapshot*` поля).
  Изменение цены ткани или пошива позже старые заказы не пересчитывает.
- Цена ткани хранится в валюте закупки + курс к THB на дату закупки
  (`purchasePrice × fxRateToThb`).
- Роль `MANAGER` денежных сумм не видит — ни на страницах, ни в выгрузке Excel.

### Дизайн

Брендовые цвета отвечают за интерфейс: Deep Ocean `#02333A` — шапка и текст,
Gold Moon `#E9924A` — акценты и денежные суммы, White Sand `#FFFAF2` — фон.
Шрифты Playfair Display (заголовки и крупные цифры) + Jost (остальное).

**Цвета данных — отдельная палитра** (`--series-1..8` в `globals.css`).
Deep Ocean и Gold Moon как цвета точек и столбцов друг от друга не отличаются
и не проходят проверку на дальтонизм, поэтому для многосерийных графиков они не
используются. Gold Moon применяется там, где ряд один. Статус никогда не
передаётся одним цветом — всегда цвет + иконка + подпись.

## Деплой

Приложению нужен постоянный сервер (не серверлесс с эфемерным диском), потому
что база и загруженные файлы лежат на диске. Подойдёт любой хостинг с
постоянным диском: Fly.io, Render, Railway, VPS.

```bash
npm run build
npm start          # слушает :3000
```

Переменные окружения на продакшене:

```
SESSION_SECRET=<длинная случайная строка>
AINUR_API_TOKEN=<токен Readonly из Ainur>
DATABASE_FILE=/data/luna.db      # на постоянном диске, не в контейнере!
```

Что важно не забыть:

1. **Диск.** `DATABASE_FILE` и папка `public/uploads` должны лежать на
   постоянном томе, иначе при перезапуске потеряются база и фото.
2. **Первый пользователь.** После деплоя запустить `npm run db:migrate`, затем
   создать владельцев — либо один раз выполнить `npm run db:seed` на пустой
   базе и потом поменять пароли, либо добавить пользователей вручную.
3. **HTTPS.** Cookie сессии помечается `secure` в продакшене — приложение
   должно открываться по https, иначе вход не сохранится.

### Переход на PostgreSQL

Если понадобится (несколько серверов, управляемые бэкапы):
`drizzle-orm/node-postgres` уже установлен. Меняется только
`src/lib/db/client.ts` (подключение) и `dialect` в `drizzle.config.ts`;
схема и весь остальной код совместимы.

### Загрузка файлов на продакшене

Сейчас фото и лекала пишутся в `public/uploads`. Для перехода на S3-совместимое
хранилище достаточно заменить функцию `saveUpload` в `src/lib/uploads.ts` —
остальной код работает с готовым URL и об источнике не знает.
